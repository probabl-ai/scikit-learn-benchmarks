Findings

On the benchmarked cases:

  • sklearnex-cpu is the most consistently fast option. Linear models gain less than tree-based models and KMeans.
  • sklearnex tree-based models are fast, but don't behave exactly like scikit-learn:
    • By default, sklearnex random forests and extra trees bin featuresMapping each feature to a small number of integer bins (a few hundred at most) before building trees. (max_bins=256Maximum number of bins per feature for histogram-based splits.), which scikit-learn doesn't implement yet. Binning roughly doubles or triples the fit speed-up. Cases run with exact splitsSplits chosen among every distinct value of the feature. (max_bins=n_samples) are on the left of each software in the tree-based plots.
    • Two oneDALoneAPI Data Analytics Library: Intel's C++ library that implements the algorithms of scikit-learn-intelex. bugs make some fits worse: oneDAL#3648 (ExtraTreesRegressor) and oneDAL#3771 (max_leaf_nodesTree parameter capping the number of leaves. With it, trees grow best-first: the most promising node is split first.).
  • sklearnex KMeans fits ~3x faster and is never slower than scikit-learn.
  • Array APIStandard API shared by array libraries (NumPy, PyTorch, CuPy, dpnp). With it, some scikit-learn estimators run directly on these libraries' arrays, including on GPU. backends are mixed. Only LogisticRegression and Ridge are benchmarked for now:

How to read

The plots read like in the software comparison above, with one color per machine. The CPU and GPU runs of a library are separate softwares, like sklearn-torch-cpu and sklearn-torch-gpu.

Random forests and extra trees often have a different forest size on each machine: their times are rescaled to the same size, and their metrics aren't compared when the sizes differ. KMeans is capped at 64 threads on machines with more than 64 CPUs, to avoid an OpenBLAS crash.

Findings

On the benchmarked cases:

  • The high-end Intel Xeon server mostly helps random forests and extra trees. With scikit-learn, their fit is ~2x to 4x faster than on the Intel Core Ultra laptop.
  • scikit-learn-intelex makes much better use of the server's 172 cores. With it, random forests and extra trees fit ~10x to 12x faster on the server than on the laptop.
  • For linear models, the server is often slower than the laptop. A single fit doesn't use many cores well, so the laptop's faster cores probably win.
  • HistGradientBoosting results are hard to interpret, because of known scalability issues on laptops with conda-forgeCommunity-maintained channel of conda packages. Its scikit-learn can be installed with different BLAS and OpenMP libraries. builds and on machines with many cores. See scikit-learn#34764 and the HistGradientBoosting thread-scalability breakdown.

Findings

On the benchmarked cases:

  • Software and hardware gains can compound. Random forests fit ~30x faster with scikit-learn-intelex on the Intel Xeon server than with scikit-learn on the Intel Core Ultra laptop, while the software alone gives ~2x to 3x and the server alone ~3x.
  • cuML on the NVIDIA L4 fits LogisticRegression ~3.5x and RandomForestClassifier ~2.5x faster than scikit-learn on the laptop. RandomForestRegressor and Ridge are often slower.
  • A big CPU server can beat that GPU: scikit-learn-intelex on the Intel Xeon server fits random forests ~20x to 35x faster than cuML on the L4, and ~1.7x to 2.5x faster on the Intel Core Ultra laptop, with 256 bins on both sides.
  • Array APIStandard API shared by array libraries (NumPy, PyTorch, CuPy, dpnp).
